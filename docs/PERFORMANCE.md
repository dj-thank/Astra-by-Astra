# 起動直後の負荷と音声の改善

2026-09-12 / `codex/solar-performance` / UE 5.8.2、Win64 DX12。

ユーザーの症状は、太陽への接近前から重く、音も途切れること。既存の実プレイログには、無制限の描画、2秒ごとの環境光キャプチャ、地形反映によるメインスレッド停止があった。実プレイの地形反映中央値は約130ms、地表マスク更新約68ms、最大のゲームスレッド停止は1.17秒。ただし、この最大停止の内訳と音切れの直接の因果関係までは特定できていない。

## 変更

- 通常設定を30fps上限にして、CPU/GPUを描画のために使い切らない。出力解像度・TSR・太陽の4K観測画像・船体の補助光・Lumenは維持。
- 地形の頂点・法線生成を既存の単一バックグラウンドワーカーへ移動。中心256、周辺128分割とし、HDR観測画像は3000から1500ピクセルの実データのoverviewを使う。地表の細かさとの交換であり、超低空で従来と同じ解像度ではない。
- 観測値の16bit→FloatRGBA変換、年代、投影、欠損時の全球地図を維持。二値の表示範囲マスクは1536×1536に縮小し、粗い画素内の欠損を保守的に判定する。81MBのテクスチャの毎回再生成をやめ、同じ小さなリソースを非同期更新する。
- 環境光キャプチャは位置、太陽方向、地形の変更時にまとめて行う。時計の進行だけで更新する間隔を2秒から30秒にする。地平線・遮蔽・直接光の判定は毎フレーム継続する。
- 太陽の目的地選択／接近予告から必要な素材だけを非同期先読み。読み終わるまでは従来の太陽、読み終わったら現在のUTCと照明値で接続する。全惑星の全素材を事前ロードしない。
- 球面を独自にサンプリングする太陽画像は、遠距離での先読みによる低いmipの残留を防ぐため、選択後はAIA・HMI・品質マスクの3枚だけを高解像度で保持する。
- 音声はパッケージ読込とストリーム先頭チャンクの準備を分け、準備完了後に再生側へ渡す。1024フレーム／48kHzを維持し、出力キューを1から2バッファへ増やす。名目上は約21ms分の余裕と遅延が増える。
- ビルド用PCHの自動削除をやめ、再利用する。旧パッケージとセーブ形式は保持。
- 長時間航行で追加の停止が出たため、診断記録のディスク書込とflushも専用スレッドへ移した。従来は操縦側と地形ワーカーが同じロックを取り、同期書込していた。待機データは約1MiBに制限し、超過時は欠落件数を次の記録に明記する。終了時に残りを保存する。クラッシュ時には未書込の末尾が失われ得る。

## 比較方法

RX 7600 XT、Ryzen 7 5700X、32GB、2560×1080、100%描画。同じUTC、同じ通常出発付近の45秒の飛行、元のEarthCacheを別の保存領域へコピー。固定時間ステップ、`-nosound`、動画用の連続スクリーンショットは使用していない。各条件1回の測定で、ネットワークやOSの変動を含む。新たに必要な1500pxのoverviewは初回にはネットワーク取得が発生する。

| 指標 | 旧版・上限なし | 旧版・30fpsのみ | 軽量版 |
| --- | ---: | ---: | ---: |
| プロセスCPU使用時間 | 181.6秒 | 71.1秒 | 62.2秒 |
| メモリ中央値 | 1944 MiB | 1931 MiB | 1406 MiB |
| 地形反映・ゲームスレッド中央値 | 174.8ms | 128.3ms | 17.4ms |
| 地表マスク更新中央値 | 86.1ms | 61.0ms | 1.8ms |
| 環境光キャプチャ回数 | 22 | 22 | 4 |
| フレーム時間99パーセンタイル | 16.78ms | 33.38ms | 33.35ms |

CPU時間は複数コア分の合計で、実時間やCPU使用率とは別の値。無制限版のフレーム時間が短いのは多く描いているためであり、上限を付ける目的は余力を戻すこと。地形の測定は各3タイル。メモリはプロセスの物理使用量で、VRAMの計測値ではない。

最初の描画準備の約0.56秒は残る。太陽の先読み終了時には立体メッシュ接続に約43msを要した。起動待ちや一時停止がすべてゼロになるという結果ではない。通常起動では開発用の画面上メッセージを非表示にし、ログは残す。近接時の高露出には既存のLumenキャッシュの露出範囲警告があり、今回の軽量化で露出系全体を再設計してはいない。

## 最終確認

非同期ログ修正後の画面外レンダリング（同じ2560×1080）の45秒ではCPU時間59.0秒、メモリ中央値1380MiB、地形反映13.8ms、マスク更新1.1msだった。表示方法が異なるため、上の通常画面表示の3条件比較とは分けて扱う。

配布フォルダの本体で通常の地球出発から太陽選択、O相当の機首合わせ、F相当の確認、自動航行、観測位置での減速・停止を295.2秒で確認した。航行許可の迂回なし、回復リセット0回、最終速度約0.08m/s。8,828件の経路検査に合格。この後に変更したのは太陽画像3枚のmip常駐だけで、最終バイナリでも4K近接・保存読込を再確認した。各試験の本体ハッシュを `validation` に残す。

最終本体の3840×2160・100%描画は、GPU中央値14.40ms、99パーセンタイル16.56ms、フレーム時間中央値33.334ms。従来太陽表示のGPU中央値14.61msとの差は測定変動の範囲で、今回の条件では追加2msの予算を超える差はなかった。全景・全PCでの性能保証ではない。

書込スレッドを意図的に250ms遅らせた状態でも、4K近接のフレーム時間99パーセンタイルは33.35ms。停止・再開・保存・時計変更・読込の5項目は全て合格。無音の約2秒はテストが指示したポーズと対応し、通常の45秒音声試験では途中の無音ブロック0。

## 音の確認と限界

軽量版45秒のゲーム内部録音と、選択中のWindowsヘッドホン出力のWASAPIループバック録音を取得。起動前後5秒を除く区間では、10msの完全な無音ブロックは0。バッファ数2、音声チャンクの準備成功を実行ログで確認した。旧版の内部録音でも無音は再現せず、ユーザーの音切れを直接再現して修復を証明できたわけではない。ループバックはWindowsが出力した音であり、Bluetooth伝送や実際に耳へ届いた音の検証ではない。

初回フレーム、ネットワーク待ち、OSやドライバの負荷は残る。音声の実機確認はこのヘッドホン出力・この区間に限る。

## 根拠と再検証

[Epic: 非同期アセット読込](https://dev.epicgames.com/documentation/unreal-engine/asynchronous-asset-loading-in-unreal-engine)に沿って素材の寿命を保持し、[音声設定](https://dev.epicgames.com/documentation/en-us/unreal-engine/platform-audio-settings-in-unreal-engine)のキュー容量と遅延の交換、[音声ストリームキャッシュ](https://dev.epicgames.com/documentation/en-us/unreal-engine/an-overview-of-audio-stream-caching-in-unreal-engine)の準備完了を利用した。[Sky Light](https://dev.epicgames.com/documentation/en-us/unreal-engine/sky-lights-in-unreal-engine)の再キャプチャは高コストなので、無条件の再実行を抑えた。Realtime Captureは取得できる描画要素に制限があるため、そのまま置き換えていない。

調査はLuna/maxの3セル、独立した出典の系列はEpicの1系列。結論はローカルのエンジン実装とWindows版の実測で照合した。

再検証は通常の音声付き可変時間ステップでCSVを記録する。`Launch-SolarQA.ps1` の固定時間・無音モードは画像比較用で、起動負荷と音声検証には使わない。`-StarNavigationQA -StarSunTransferQA -StarNavigationPath=<新しい絶対パス>` は通常の地球出発から目的地選択、O相当、F相当、太陽への到着を検査する最大600秒の専用ドライバー。通常の航行許可を迂回せず、天体座標更新後の位置から連続性を確認する。物理キー操作の試験ではない。

ゲーム本体とエディタDLLのコンパイルは成功。エディタDLLのロードと一部ネイティブテスト実行はWindowsのアプリ制御で拒否された。画像・マテリアルに変更がないため、既存のcook済み素材を使って新しい本体と設定をstageし、実際に起動した。未実行のネイティブテストをPASSとは扱わない。
