保存形式、観測データ、素材、出典・ライセンス、公開リリースは変更しません。

## 追加修正

- 入力校正・応答曲線・安全条件を、読込時だけでなく入力処理の入口でも検証。不正な時計値は入力を消して再アームを要求します。
- 月面歩行の初期化と天体フレーム更新は、候補全体の検証後に反映。失敗時には現在の歩行位置・乗船口を保持します。移動中、ギア未展開、無効な姿勢の船からの降船を拒否します。
- 地形のグリッド・座標系・補間境界を数値変換前に検証。法線や継ぎ目用サンプルの欠損を、正規化のフォールバックで隠して完成扱いしません。キャッシュ一致条件に半径と座標軸も含めます。
- TIFFの再読込は、全タイル成功後にデータと属性を一括交換。失敗・最終タイルでのキャンセル時も以前の画像を保持し、成功時は古いエラーを消します。符号付き・未対応形式や範囲外seekは拒否します。
- セーブの飛行状態と発見記録の復元が成功してから旧EVAキャラクターを破棄し、船への操作・視点・音声を復元します。失敗したロードは旧キャラクターを破棄しません。新EVAの復元に失敗した場合も古いキャラクターを残しません。
- GCCの警告をエラーとして扱う既存テストで、紛らわしいインデントと一時文字列を受けるテスト用参照引数を修正。警告の抑制やテストの削除はしていません。

## 再実行

Windows（VS C++ Build Tools、PowerShell 7、Python 3）:

```powershell
./Tools/Simulation/Test-Robustness.ps1
```

Linux / GCC・Clang:

```sh
python3 Tools/Testing/run_native.py --compiler g++ --jobs 2
python3 Tools/Testing/run_native.py --sanitize --compiler clang++ --jobs 2
```

TIFF実デコード（libtiff開発ヘッダーとpkg-configが必要）:

```sh
python3 Tools/Testing/run_raster_decode.py --sanitize --compiler clang++
```

一時生成物・試験用TIFF・ビルドログは `work/` にのみ出力します。
CIではWindowsの回帰試験と、LinuxのGCC・Clang sanitizer・libtiff試験を実行します。

## 何を確認できるか

15本のネイティブ実行ファイルは、飛行、観測、連続世界、航法、音声DSP、入力コア、EVA、地形、抽出したコントローラー処理を検証します。
地形には通常・極・経度境界の生成グリッドを含み、入力では16ビット入力値全域を走査します。

TIFF試験は**本番の `FStarRemoteRaster::Load` と `Seek` をソースから抽出**し、実際のlibtiffで生成・デコードしたローカル画像に、読込失敗と最終タイルでのキャンセルを注入します。
EVA試験も本番の後処理を抽出し、さらにLoadGame内での呼出順序を静的に検証します。
これらはUEやHTTP自体を再現したものではなく、接続部分を小さなホスト用アダプターに置き換えた試験です。

## 未検証の受入条件

- 正規に導入したUnreal Engineで全ゲームをビルドし、Win64パッケージを生成する。
- ゲーム内で「EVA→船のみのセーブ」「EVA→別EVAのセーブ」「EVA→破損したセーブ」「EVA復元不可」の各読込を行い、操作対象・カメラ・アクター数・音声・一時停止を確認する。
- 実HTTPの部分取得、キャンセル、タイムアウト、壊れたキャッシュからの再取得を確認する。
- 実際の観測DEM・画像で描画、衝突、座標変換、地形の継ぎ目を確認する。
- 実コントローラー、音声デバイス、VR、パッケージ環境での表示と操作を確認する。

合成された平地・球面は数値検証用であり、観測データの精度検証ではありません。
ネイティブ試験成功をUEビルド・実機合格や「バグゼロ」の証明として扱いません。
